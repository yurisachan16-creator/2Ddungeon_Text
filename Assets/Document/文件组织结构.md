## 文件分类说明

### 🔧 核心框架层（StateMachine/）
**用途**: 提供状态机的基础功能，与具体角色无关
- **IState.cs**: 定义状态必须实现的4个方法（OnEnter/OnUpdate/OnFixedUpdate/OnExit）
- **StateMachine.cs**: 管理状态切换、缓存、生命周期

**特点**:
- ✅ 通用性强，可用于任何需要状态机的系统
- ✅ 无需修改，直接使用
- ✅ 支持状态缓存，性能优化

---

### 👤 角色系统层（Character/）

#### CharacterBase.cs - 角色基类
**用途**: 所有角色的父类，提供通用属性和方法

**包含内容**:
- 基础属性：生命值、移动速度、攻击力
- 状态标志：是否死亡、受伤、攻击中
- 组件引用：Rigidbody2D、Animator、SpriteRenderer
- 通用方法：TakeDamage()、Heal()、Die()

**使用方式**: 创建新角色时继承此类
```csharp
public class NewCharacter : CharacterBase { }
```

---

#### Knight/ - Knight角色实现
**角色定位**: 近战玩家角色，由玩家输入控制

**文件说明**:
- `KnightController.cs`: 主控制器，处理输入和攻击判定
- 各State文件: 每个文件对应一个状态，负责该状态的所有逻辑

**状态流转**:
```
Idle → Move → Idle
  ↓      ↓
Attack01/02 → Idle
  ↓      ↓
Hurt → Idle
  ↓
Death (终态)
```

**输入控制**:
- WASD: 移动（MoveState）
- 鼠标左键: Attack01
- 鼠标右键: Attack02

---

#### RangedEnemy/ - 远程敌人实现
**角色定位**: AI控制的远程敌人，自动攻击玩家

**与Knight的区别**:
| 特性 | Knight | RangedEnemy |
|------|--------|-------------|
| 控制方式 | 玩家输入 | AI自动 |
| 攻击方式 | 近战检测 | 发射投射物 |
| 状态数量 | 6个 | 4个（无移动状态）|
| 使用场景 | 玩家角色 | 敌人AI |

**AI逻辑**:
1. Idle: 检测玩家进入范围
2. Attack: 保持距离，定时发射投射物
3. Hurt/Death: 受击反馈

## 代码规范

### 命名约定
- **类名**: 大驼峰 + 后缀（如 `KnightIdleState`）
- **文件名**: 与类名完全一致
- **命名空间**: 暂未使用（小型项目）

### 状态类命名规范
格式: `{角色名}{状态名}State`

示例:
```
KnightIdleState
KnightAttack01State
RangedEnemyAttackState
```

### 目录组织原则
1. **按功能分类**: StateMachine/、Character/
2. **按角色分组**: Knight/、RangedEnemy/
3. **一角色一文件夹**: 所有状态放在同一目录下
4. **控制器放在首位**: Controller.cs文件排在状态文件前

## 扩展指南

### 添加新角色类型
1. 在`Character/`下创建新文件夹：`Assets/Scripts/Character/YourCharacter/`
2. 创建控制器：`YourCharacterController.cs`
3. 创建状态文件：`YourCharacterIdleState.cs` 等
4. 在控制器中初始化状态机

### 添加新状态
1. 在对应角色文件夹下创建：`CharacterNameNewState.cs`
2. 实现IState接口的4个方法
3. 在其他状态中添加转换条件

### 修改现有角色
- **修改属性**: 编辑`Controller.cs`或`CharacterBase.cs`
- **修改状态逻辑**: 编辑对应的`State.cs`文件
- **添加输入**: 在`IdleState`或`MoveState`的`OnUpdate()`中添加检测

## 性能考虑

### 状态缓存
- StateMachine使用Dictionary缓存状态实例
- 避免每次切换都创建新对象
- 适合频繁切换的场景

### 物理计算
- 移动操作放在`OnFixedUpdate()`
- 减少Update中的GameObject.Find
- 使用Singleton模式缓存常用引用
